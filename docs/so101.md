# Running stepscope on an SO-100 / SO-101 arm

Status: the bridge (`src/stepscope/adapters/lerobot_robot.py`) is tested against a
simulated stand-in with the same interface as LeRobot's SO follower. It has not been
run on hardware. Follow the steps in order; the first runs change nothing about how
your arm moves.

The gate is a software check. Keep a hand on the power switch and do not rely on it as
an emergency stop.

## 1. Install

```bash
pip install -e . "lerobot[feetech]" mujoco
```

## 2. Check the joint mapping (do this before trusting any limit in space)

stepscope works out where the arm is in space from its joint angles, using a model of
the SO-101. LeRobot reports each joint relative to its calibration, which may not match
the model's zero pose or direction. Check it once:

```python
from lerobot.robots.so_follower import SO101Follower, SO101FollowerConfig
from stepscope.adapters.lerobot_robot import JointMap, SO101_MOTORS, so101_kinematics

robot = SO101Follower(SO101FollowerConfig(port="/dev/ttyACM0"))
robot.connect()
kin, joints = so101_kinematics(), JointMap()

obs = robot.get_observation()
q = [obs[f"{m}.pos"] for m in SO101_MOTORS]
print("gripper tip (x, y, z) in metres:", kin.points(joints.to_model(q))[-1])
```

Put the arm in two or three poses you can measure and compare the printed gripper
position with a ruler. The model's frame has its origin at the base, z up, and the arm
reaches along -y when every joint is at zero. If a joint moves the wrong way set its
`sign` to -1; if it is offset, set `zero_deg`:

```python
joints = JointMap(sign=[1, -1, 1, 1, 1], zero_deg=[0, 90, 0, 0, 0])
```

## 3. Run in shadow mode

In shadow mode the gate judges every action and records its verdict, but the action
sent to the arm is exactly what your policy asked for.

```python
from stepscope import TraceConfig, Tracer
from stepscope.adapters.lerobot_robot import StepscopeGuard, so101_gate

gate = so101_gate(
    kin, joints,
    max_step_deg=6.0,                                   # most any joint may move per step
    workspace=([-0.45, -0.50, -0.02], [0.45, 0.25, 0.55]),
    keep_out=[{"name": "operator side", "center": [0.0, -0.30, 0.10], "radius": 0.12}],
)
tracer = Tracer("runs/so101", config=TraceConfig(max_steps=600), gate=gate, shadow=True)

def my_policy(observation):
    # your ACT policy here; return the six target positions in SO101_MOTORS order
    ...

guard = StepscopeGuard(robot, my_policy, tracer, kinematics=kin, joint_map=joints, camera_key="front")
summary = guard.run_episode(task="pick up the block", max_steps=600, hz=30)
print(summary["guard"])   # how often the gate would have stepped in, and the time it added per step
```

Then look at the run:

```bash
stepscope serve --runs runs
```

Check that the 3D view matches what the arm did, and look at the steps where the gate
would have stepped in. If it flags normal motion, loosen the limits; if it misses
something it should catch, tighten them.

## 4. Turn enforcement on

Only when the shadow runs look right:

```python
tracer = Tracer("runs/so101-enforced", config=TraceConfig(max_steps=600), gate=gate, shadow=False)
```

Now the gated action is the one sent. A move that would enter a keep-out zone is
shortened or held, and a halt holds the arm at its current position.

## Tracing an ACT policy's internals

Return a dict from your policy instead of an array to trace more:

```python
def my_policy(observation):
    ...
    return {
        "action": target,                 # (6,)
        "samples": sampled_targets,       # optional (N, 6): alternatives, e.g. from dropout
        "internals": {"attention": attn_map, "embedding": embedding},   # optional arrays
        "belief": {"subtask": "reaching"},                               # optional
    }
```

`src/stepscope/adapters/lerobot_aloha.py` shows how these are read out of an ACT model
(`ACTAlohaPolicy.infer`): the decoder's cross-attention over the image, the encoder
embedding, and dropout samples as candidate plans.

## What has and has not been checked

- Checked in simulation: the guard never changes the action in shadow mode; in enforce
  mode the arm stays out of a keep-out zone placed on its path; a halt holds position;
  the added time per step is a few milliseconds.
- Not checked: anything on a physical arm, including the joint mapping, timing over the
  serial bus at 30 Hz, and how the arm behaves when a move is shortened mid-motion.
